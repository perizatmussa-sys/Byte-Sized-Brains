# Byte-Sized-Brains — CQA Hackathon

## Быстрый запуск (Windows)

Дважды щёлкните **`start.bat`** в папке проекта (рядом с папкой `backend`). Он сам создаст `.venv`, установит пакеты и запустит сервер; затем откройте http://127.0.0.1:8001. Ключи и ссылку API положите в файл `.env` в той же папке.

## Этап 5: GroqCloud + Google Gemini API + апелляции

Программа показывает диалоги, позволяет оценивать их вручную и автоматически через **двух разных AI-провайдеров**.

* **GroqCloud**: модель `qwen/qwen3.8-27b`.
* **Google Gemini**: модель `gemini-3.5-flash-lite`.
* **Авто**: сначала Groq, если запрос не удался — Gemini.
* **Сравнение**: оба AI оценивают один диалог независимо; сайт показывает разницу.
* **Кеш**: уже сохранённая оценка для того же диалога, модели и чек-листа используется повторно **без расхода токенов**. Галочка «Оценить заново» принудительно делает новые запросы.

На оценке по-прежнему используются исходные 8 критериев чек-листа. Человек может менять критерии через интерфейс. Python самостоятельно проверяет значения, допустимость N/A, индексы сообщений и математически рассчитывает итог. AI не доверяют слепо. Ручные результаты `data/evaluations.json` не перезаписываются AI; результаты AI разных моделей — в `data/ai_evaluations.json`.

**Добавлены апелляции и пересмотр проверяющего.** Результаты моделей могут различаться или содержать ошибки, поэтому человек может оспорить отдельный критерий. Исходная оценка при этом не перезаписывается.

## Новый дизайн: лендинг + рабочее пространство оценки

* **Лендинг** на весь экран (тёмно-синий фон): «Проверяйте качество работы операторов с помощью AI», кнопка «Попробовать бесплатно». Страница не прокручивается колесом — вниз переходим только по кнопке; «На главную» возвращает наверх.
* **Рабочее пространство** с боковым меню:
  * **Оценка диалогов** — фильтры «Канал» и «Язык», поиск по ID или тексту, сортировка по баллу, бейдж балла у каждого диалога; вкладки «AI-оценка / Ручная оценка»; транскрипт с аватарами (и плеер, если есть запись); панель «Итоговый балл» со статусом («Соответствует», «Частично», …) и списком критериев в процентах — клик по критерию показывает реплику-доказательство.
  * **Апелляции** — таблица всех обращений с фильтром по статусу.
  * **Ревью** — очередь открытых апелляций для проверяющего.
  * **Аналитика** — оценено / средний балл / доля соответствующих / грубые нарушения, выполнение критериев, распределение баллов, сравнение по каналу и языку, худшие диалоги.
  * **Чек-лист** — редактор критериев (количество не ограничено).
* **Скачивание**: отдельный скрипт (TXT/JSON) и все скрипты текущего канала одним файлом.
* **Добавить свои диалоги** (раздел в боковом меню): вставить текст («Оператор: …», «Клиент: …», время по желанию), загрузить файлы `.txt` / `.json` (формат API организаторов тоже подходит) или загрузить контрольный набор по `group_id`. Свои диалоги хранятся в `data/custom_records.json`, DEV не трогается; кнопка «Оценить с AI все добавленные без оценки» обрабатывает их пакетно.
* **Апелляция по нескольким критериям**: в карточке диалога отметьте несколько критериев, у каждого свой комментарий (или общий). Проверяющий открывает её из «Ревью» на отдельной странице «Карточка апелляции» и принимает решение по каждому критерию; итог пересчитывается один раз. Старые апелляции с одним критерием продолжают работать.
* Логотип Freedom Broker — `frontend/logo.png` (белый на прозрачном фоне).
* **Выбор скрипта**: вместо длинного списка — выпадающий список «Скрипт для проверки» (группы: звонки, переписки, свои), кнопки «Случайный» и «Добавить свой».
* Новые API: `GET /api/scores`, `GET /api/appeals/all`, `GET /api/appeals/{id}`, `POST /api/conversations` (свои диалоги), `DELETE /api/conversations/{id}`, `POST /api/import?group_id=...`, `GET /api/conversations/{id}/download?format=txt|json`, `GET /api/export?kind=all|call|chat&format=txt|json`; в списке диалогов есть поля `kind` (`call`/`chat`) и `search_text`.

## Этап 5. Апелляции (основное требование хакатона)

### Что теперь есть

1. Под любым открытым диалогом появилась секция **«Апелляции и пересмотр»**.
2. Пользователь выбирает источник сохранённой оценки: **ручная**, **GroqCloud** или **Gemini**, затем конкретный критерий и пишет комментарий.
3. Нажимает **«Подать апелляцию»**. Программа сохраняет исходную оценку, причину и доказательство.
4. Проверяющий (на той же странице — вход по заданию не требуется) читает спор и выбирает **«Подтвердить»** или **«Изменить»**, пишет причину.
5. При изменении выбирает новую оценку и реальную реплику-доказательство, затем сохраняет решение. **Python пересчитывает итог по тому чек-листу, по которому оценка была получена**.
6. История содержит исходную оценку, решение, комментарий проверяющего и **финальный результат**. Groq/Gemini снова не вызываются — на пересмотр токены не тратятся.

### Установка поверх Stage 4

**Перед распаковкой убедитесь, что ваши прошлые изменения закоммичены.** Не удаляйте `.env`, `.venv` или папку `data`.

```powershell
cd D:\Byte-Sized-Brains
git status
# Если рабочее дерево чистое и Stage 4 уже сохранён:
git switch -c feature/appeals
Expand-Archive -LiteralPath ".\Byte-Sized-Brains-stage5-APPEALS.zip" -DestinationPath "." -Force
Remove-Item ".\Byte-Sized-Brains-stage5-APPEALS.zip"
python -m unittest discover -s tests -v
python -m uvicorn backend.main:app --reload
```

Откройте http://127.0.0.1:8000, нажмите `Ctrl+F5`, выберите диалог с ранее сохранённой оценкой, прокрутите вниз до блока апелляций. Для первого опыта оспорьте критерий «Завершение» — тогда можно легко увидеть разницу баллов при пересмотре.

**Проверка тестов:** на версии Stage 5 проходят 25 тестов (включая 11 тестов апелляций). Настоящий AI запрос для проверки апелляции не нужен.

**Совместимость со старыми оценками:** ранние записи Stage 4, не содержащие сохранённой копии чек-листа, можно пересмотреть, если версия и структура чек-листа не менялись. Если менялись, программа предложит получить новую оценку вместо опасного пересчёта по другим правилам.

### Новые API

- `GET /api/appeals?conversation_id=ID` — история апелляций для диалога.
- `POST /api/appeals` — `{"conversation_id":"...","source":"groq","criterion_id":"closing","comment":"..."}`.
- `POST /api/appeals/{appeal_id}/decision` — `{"action":"confirm","reason":"..."}` или `{"action":"change","new_value":"yes","evidence_index":1,"reason":"..."}`.

**Данные хранятся локально** в `data/appeals.json` и исключены из Git через `data/*`. Не выкладывайте текст клиентов, результаты апелляций и `.env` в публичный репозиторий. Для демо используйте текущие локальные данные.

## Установка в существующем проекте на Windows

1. **Не удаляйте** локальные `.env`, `.venv` и папку `data`. Проверьте Git перед обновлением:

   ```powershell
   cd D:\Byte-Sized-Brains
   git status
   ```

2. Скопируйте ZIP обновления в `D:\Byte-Sized-Brains` и выполните:

   ```powershell
   Expand-Archive -LiteralPath ".\Byte-Sized-Brains-stage4-DUAL-AI.zip" -DestinationPath "." -Force
   Remove-Item ".\Byte-Sized-Brains-stage4-DUAL-AI.zip"
   ```

3. Для этой версии **не нужны новые библиотеки**: достаточно `requests`, `FastAPI`, `python-dotenv`, `uvicorn` из прежнего `requirements.txt`. Если нужно, установите:

   ```powershell
   python -m pip install -r requirements.txt
   ```

4. Получите API-ключи (достаточно одного для начала):
   - Groq: https://console.groq.com/keys
   - Gemini: https://aistudio.google.com/api-keys

5. Откройте **существующий** `.env`: `notepad .env`. Добавьте строки ниже, **не удаляя `CQA_API_URL`**:

   ```dotenv
   GROQ_API_KEY=ваш_ключ_Groq
   GROQ_MODEL=qwen/qwen3.8-27b
   GEMINI_API_KEY=ваш_ключ_Gemini
   GEMINI_MODEL=gemini-3.5-flash-lite
   CQA_ALLOW_REAL_CALLS=false
   ```

   Если уже есть строки `GROQ_...`, просто сохраните их и добавьте отсутствующие `GEMINI_...`. Настоящие ключи и `sig` никогда не коммитьте в GitHub. Free Tier имеет лимиты; плата и доступ к API зависят от настроек аккаунта.

6. Проверьте Python-код без обращения к API:

   ```powershell
   python -m unittest discover -s tests -v
   ```

   На версии архива должно быть 14 пройденных тестов.

7. Перезапустите сервер:

   ```powershell
   python -m uvicorn backend.main:app --reload
   ```

   В браузере откройте http://127.0.0.1:8000 и обновите страницу (`Ctrl + F5`). Выберите **синтетический текстовый чат**, затем режим и кнопку **«Оценить с AI»** или **«Сравнить Groq и Gemini»**.

8. Посмотрите расход токенов под каждой AI-оценкой. Проверьте обработку RU, KZ, EN; оценки могут быть неточными. Для следующего показа используйте уже сохранённые результаты.

## Как работают кнопки

- **Авто: Groq → Gemini** — один ответ. Если Groq не отвечает/лимит/ключ отсутствует/невалидная оценка, программа пробует Gemini. Использованный провайдер указывается явно.
- **Только Groq / Только Gemini** — вызывается только выбранный провайдер.
- **Сравнить Groq и Gemini** — оба провайдера анализируют один и тот же чат. Сохраняет обе оценки; отдельный общий балл **не усредняется автоматически**.
- **Оценить заново** — расходует токены; без галочки результаты берутся из локального кеша, если тот подходит к текущему чек-листу, диалогу и модели.

## API

- `GET /api/ai/status` — какие ключи настроены, какие модели выбраны; сами ключи не возвращаются.
- `POST /api/ai/evaluations/{id}?provider=auto|groq|gemini&force=false` — одна оценка с возможностью резерва.
- `POST /api/ai/compare/{id}?force=false` — две оценки, сравнение итогов, возможные частичные ошибки.
- `GET /api/ai/evaluations/{id}` — сохранённые оценки: `{ "groq": ..., "gemini": ... }`.
- Остальные существующие маршруты: `/api/import`, `/api/conversations`, `/api/checklist`, `/api/evaluations/{id}`.

## Приватность и безопасность

**Пять реальных voice call из набора DEV запрещены к отправке в оба внешних AI по умолчанию.** Сначала получите разрешение организаторов и проверьте требования по конфиденциальности. Даже в синтетических чатах стоит проверить отсутствие реальных персональных данных. Учтите: на бесплатном Gemini-тарифе переданные данные могут использоваться Google для улучшения сервисов.

Нельзя публиковать `.env` (в том числе полный CQA API URL с `sig`) и содержимое `data`. Проверьте Git:

```powershell
git check-ignore .env data/dev_records.json data/ai_evaluations.json
git ls-files .env data/dev_records.json data/ai_evaluations.json
git status
```

Если `git ls-files` показывает конфиденциальный файл, остановитесь и исключите его из отслеживания до push.
