# Byte-Sized-Brains — CQA Hackathon

## Текущая версия: Этап 2

Готово:
- Подключение к DEV API, загрузка и просмотр 65 диалогов (текст + ссылка на аудио).
- Редактируемый чек-лист из восьми критериев по PDF с добавлением и удалением критериев.
- Ручной тест оценки по каждому критерию с объяснением и привязкой к настоящей реплике.
- Подсчёт баллов (Да/Нет, числовые шкалы, N/A, перераспределение до 100, округление до 2 знаков, отдельный флаг грубой ошибки).
- Сохранение оценок и настроек на локальном компьютере.

**ЕЩЁ НЕТ AI-оценки и апелляций.** Ручная форма сейчас нужна, чтобы проверять правила и математику до подключения модели. Не представляйте её жюри как AI-оценку.

## Windows, PowerShell

```powershell
cd D:\Byte-Sized-Brains
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m uvicorn backend.main:app --reload
```

Перейдите на http://127.0.0.1:8000/ . Если это новый компьютер:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

В `.env` добавьте полную ссылку GET DEV после `CQA_API_URL=`. **Не добавляйте `.env` и реальные записи в GitHub.**

## Проверка второго этапа

1. Нажмите «Загрузить DEV из API» (если данные ещё не загружены).
2. Выберите диалог слева, прокрутите до секции «Оценка диалога».
3. В тестовой ручной форме выберите ответы, напишите объяснения, укажите реплику-доказательство и сохраните.
4. Убедитесь, что баллы рассчитаны, результат сохранён, а ссылка на доказательство подсвечивает нужное сообщение.
5. Внизу страницы в «Настройка чек-листа» измените вес или добавьте новый критерий, нажмите «Сохранить чек-лист».
6. Повторно оцените разговор: используется новая конфигурация. Старые сохранённые оценки сохраняют номер прошлой версии, пока их не переоценили.

**Важно:** чек-лист по умолчанию повторяет выданный PDF. Если меняете правила, версия настроек увеличивается. Проверяющий должен выбирать N/A только если выполнено условие из PDF. Ручная форма не способна проверить истинность объяснения.

## API

- GET `/api/status` — состояние
- POST `/api/import` — импорт DEV
- GET `/api/conversations` — список
- GET `/api/conversations/{id}` — транскрипт
- GET `/api/checklist` — чек-лист
- PUT `/api/checklist` — изменить чек-лист
- POST `/api/evaluations/{id}` — сохранить ручную оценку
- GET `/api/evaluations/{id}` — последняя оценка
- GET `/docs` — документация FastAPI
